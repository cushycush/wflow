# wflow 1.3.0: Hand-edit the KDL right next to the canvas

1.3.0 adds a view-source pane to the workflow editor. Click `</> Source`
in the editor toolbar and a panel slides in from the right of the
canvas showing the current workflow as KDL, syntax-highlighted,
re-encoded live as you change the canvas. You can edit the KDL
directly: typing into the pane parses on a short debounce and
round-trips back to the canvas through the same `apply_kdl_source`
path the rest of the editor uses.

Plus a few smaller things that piled up over the release window: the
floating navpill turned into a flat top app bar, KDL fragments now
travel through the system clipboard the same way regular text does,
and dropping a `.kdl` file on the canvas imports its steps where you
dropped it.

## The view-source pane

`</> Source` is a new toggle in the editor's top toolbar. Flip it and
a 520-wide panel slides in from the right showing the workflow as KDL,
with the same syntax colors the rest of the editor uses for KDL
previews. Two-way: canvas edits re-encode into the pane on the fly,
and edits in the pane re-apply to the canvas.

Editing works the way you'd expect: type into the pane and the canvas
updates on a 600ms debounce. Tab inserts 4 spaces (the indent the KDL
encoder writes, so what you type lines up with what hits disk).
Broken KDL surfaces a coral "● unparsed" chip in the pane's header
with the parse error in a tooltip, and the canvas holds at its last
good state until you fix the source or click out of the pane.

Card positions survive a round-trip. `apply_kdl_source` calls a
`preserve_step_ids` helper that walks the old and new step lists in
order and copies the existing `_id`s onto matching new steps, using
`std::mem::discriminant` of the action variant as the match. Adding
or removing a line in the source pane doesn't trigger a layout pass
for the unchanged cards; the new card lands at the canvas default
and the camera zooms to fit the union.

Last-edit-wins on focus-loss. Clicking a canvas step while the pane
holds a broken draft snaps the pane back to canonical and discards the
draft. This matches how everywhere else in the editor treats the
canvas as the source of truth the moment a canvas action lands.

## Live syntax highlighting via a `QSyntaxHighlighter`

The first stab at highlighting rebuilt HTML from the token spans and
stuffed it into the `TextEdit` as RichText. That works for a static
read-only view but fights the cursor on every rebuild: Qt's RichText
document model can't tell a re-render from an edit, so the caret
drifts and the document state diverges from the canonical text the
user thinks they're editing. I chased that for four attempts before
going to a proper highlighter.

`cpp/kdl_syntax_highlighter.h` is a `QSyntaxHighlighter` subclass that
attaches to the body TextEdit's `QTextDocument` from QML via a
`textDocument` property. On every textChanged during edit, the pane
calls `wfCtrl.tokenize_kdl` on the local buffer and feeds the spans
JSON to the highlighter; the highlighter parses it once and runs
`highlightBlock` per text block, applying `QTextCharFormat` ranges via
`setFormat`. The document itself isn't rebuilt. The cursor stays where
the user left it.

Two subtleties worth knowing about. Once any `QTextCharFormat` lands
on the document, the QML `TextEdit`'s `color` property stops working
as a render-time fallback for unformatted ranges, so chars not covered
by a token span end up with an unset foreground and effectively
invisible. The highlighter primes every block with a `defaultColor`
(driven from `Theme.text`) before applying per-token formats, which
keeps the un-highlighted characters readable. And the `Binding on
body.text` uses `restoreMode: Binding.RestoreNone`; Qt's default
actively restores the property to its pre-binding value (`""` for
TextEdit.text) when `when` flips false, which wiped the entire
document the moment the user typed. `RestoreNone` keeps the last
binding-driven value when the binding releases.

The `cpp/` directory is new in this release. `cxx-qt-build`'s
`.cpp_file()` compiles and mocs the header, and a tiny bridge at
`src/bridge/kdl_highlight.rs` exposes a `register_kdl_qml_types()`
function that `main.rs` calls before `QQmlApplicationEngine::load`, so
`import Wflow 1.0; KdlSyntaxHighlighter {}` resolves at QML parse time
alongside the cxx-qt-registered types.

## Flat top app bar replaces the floating navpill

The pill that floated over the canvas was sitting in the same vertical
space the editor toolbar wanted to occupy, so the toolbar had to dodge
it (`topMargin` workarounds in WorkflowPage and SettingsPage). The new
top app bar sits flush at the top of the window. The doc-tab strip
and editor toolbar align underneath it with no orphan-tab gap. The
dodge workarounds are gone.

## KDL on the clipboard, KDL on a drop

Two paths into and out of the editor that round-trip through KDL.
Right-click a card and Copy as KDL writes the encoded kdl fragment to
the system clipboard through arboard (wlr-data-control with X11
fallback), so a paste in any text app gives you the source. Multi-
selection copies all selected top cards as one fragment. Paste back on
the canvas (Ctrl+V or right-click + Paste KDL) inserts at the current
crumb and dedupes any inner cards of an already-selected top.

Dropping a `.kdl` file on the canvas imports its steps. Single-file
drops land at the current crumb with a coral wash flashing on the
canvas; multi-file drops loop over the URLs. The same
`decode_fragment_str` path the deeplink import uses, so a `.kdl` file
reaches the editor through any route a file manager gives you.
