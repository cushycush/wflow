# wflow 1.0.2: Flatpak polish

Two small fixes spotted while verifying the v1.0.1 Flatpak build
against the Flathub submission checklist. Cut as a patch so the
Flathub PR can carry both.

## Record-can't-start now reads correctly inside the Flatpak

The recorder error dialog used to suggest two fixes when no capture
backend was reachable: install or restart `xdg-desktop-portal`, or
add yourself to the `input` group so the evdev fallback can read
`/dev/input/event*`. Both came from wdotool-core's upstream error
text. The second one is misleading inside a Flatpak sandbox: the
sandbox blocks `/dev/input` regardless of host group membership, so
adding yourself to `input` on the host changes nothing for the
sandboxed app.

The bridge now wraps the upstream error with
`flatpak_aware_recorder_error`. Inside Flatpak the "Pick one of
these to fix it" footer gets replaced with sandbox-specific guidance:
install or restart `xdg-desktop-portal` on Plasma 6 / GNOME 46+ (the
RemoteDesktop interface lands in the portal and the recorder uses
it without `/dev/input` access), or install the AUR `wflow` /
`wflow-bin` package or the prebuilt tarball if you're on Hyprland or
Sway today (Hyprland's portal doesn't ship RemoteDesktop yet; the
non-sandboxed builds run outside the sandbox and read `/dev/input`
directly).

Outside the sandbox the original wdotool-core text is unchanged.

## ExplorePage Row layout warning

`ExplorePage.qml:334:29: QML Row: Cannot specify left, right,
horizontalCenter, fill or centerIn anchors for items inside Row.`
fired on every launch. The "See all featured →" lockup put a Text
with `verticalCenter` and a `MouseArea` with `anchors.fill` directly
inside a Row, both fighting Row's own positioning. Restructured to
a wrapper Item with the Row and MouseArea as siblings. No visible
behavior change; the journal stops complaining.

## Upgrading

Drop-in. Both fixes are display-side. AUR users get it via
`pacman -Syu wflow`; tarball users grab the new release. The
Flathub submission tracks this version onward.
