# wflow 1.4.0: KDE Plasma 6 input + window ops

wflow 1.4.0 ships mostly so KDE Plasma 6 users get the wdotool-core
fixes that landed upstream over the last couple of weeks. Drift comes
along as a third brand palette in the same release.

## KDE Plasma 6 input and window ops

wdotool-core 0.5.0 to 0.5.3 brings three KDE-side fixes:

- 0.5.1 fixed the libei timeout triad that was blocking KDE
  verification.
- 0.5.2 fixed libei input on Plasma 6, with a flush plus two-stage
  seat.bind.
- 0.5.3 fixed window ops on Plasma 6.

For wflow itself this is a lockfile-only change. `Cargo.toml` already
pinned `"0.5"`, so `cargo update -p wdotool-core` picked the new patch
on its own. No wflow code touched.

## Drift, a third brand palette

wflow was shipping two skins, Warm Paper (the wflows.io marketing
identity) and Cool Slate (the original brief). Drift is a third,
named after a separate OS project I'm building. The goal is for wflow
to feel native when it runs on Drift.

Slate-900 dark / cream-200 light surfaces with a gold-500 accent. The
category chips lean on a slate/gold-adjacent brand-tier set (plum,
steel, sage, teal, ochre, terra) so they stay in the same register as
the surfaces.

Settings gets a third segmented-control entry. The first-run tutorial
tile row goes from 2-up to 3-up. `Theme.qml`'s `_pl` helper picks
palette tokens via six args instead of four. The Rust validator
accepts `"drift"` alongside `"warm"` and `"cool"`; older `state.toml`
files round-trip unchanged because unknown values still coerce to
`"warm"`.
