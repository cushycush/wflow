# wflow

A macOS Shortcuts-style GUI and workflow engine for Wayland, built on
[wdotool](https://github.com/cushycush/wdotool). Composes input automation,
shell, delays, and notifications into shareable `.kdl` workflow files.

---

## Design Context

### Users

General Wayland users on GNOME / KDE / Hyprland who want a friendly GUI
alternative to shell scripts. Keyboard-first power users who still expect
a product that feels at home alongside other modern desktop apps.

Primary job-to-be-done: _"I keep doing this sequence of things by hand,
let me record it once, name it, and replay it."_

Secondary: sharing workflows as single `.kdl` files (paste on Reddit,
commit to a dotfiles repo, hand to a friend).

### Brand Personality

**Modern product UI with two skins.** Three words: **calm, confident,
contemporary.**

Lives alongside Linear / Arc / Raycast / macOS Shortcuts / modern API
clients. Thoughtful spacing, flat surfaces, subtle elevation by step,
functional color on category chips, clean sans typography.

Emotional goal: **this recedes behind the task.** The app someone uses
every day and stops noticing.

### Aesthetic Direction

**Visual references:**
- macOS Shortcuts (both modes), sidebar + main pane, rounded rectangles,
  color-coded action categories, clean typography
- Linear, calm surfaces, subtle elevation, hairline borders, restrained
  accent
- Raycast, keyboard-first, dense but legible, functional color
- Requestly / Postman, method chips as colored tags, clear hierarchy
- Arc settings, Things 3, Notion
- wflows.io, the marketing site, which is the canonical Warm Paper
  identity

**Anti-references** (must NOT look like):
- Editorial / magazine layouts
- Modular synthesizer / rack aesthetics
- Glassmorphism, neon-on-dark, purple-to-blue gradients
- Skeuomorphic hardware details, screws, jacks, patch cables, LEDs
- Dense dashboard SaaS templates (cards everywhere, generic drop shadows)
- Bouncy / elastic animation

### Palettes, three brand skins, one source of truth

wflow ships three brand palettes. The active one is set on first run
via the tutorial and persists in `state.toml`; users can flip any time
from Settings. All three support light + dark.

**Warm Paper** (default, mirrors wflows.io): warm-cream surfaces (hue
55-60, near-white at L≈0.97 light, warm near-black at L≈0.16 dark) with
a coral accent (hue 25-32). This is the published marketing-site
identity.

**Cool Slate** (the original brief): slate-blue surfaces (hue 260, low
chroma) with a warm amber accent (hue 60).

**Drift** (the third skin): slate-900 dark / cream-200 light surfaces
with a gold-500 accent (hue 40-45). Reads as architectural parchment
on dark, warm vellum on light. Chip tints come from a slate/gold-
adjacent brand-tier set (plum, steel, sage, teal, ochre, terra) so
categories stay in the slate-gold register.

`qml/Theme.qml` is the canonical token registry. Every color resolves
through `_pl(coolDark, coolLight, warmDark, warmLight, driftDark,
driftLight)`, which reads both `palette` and `isDark` and returns the
matching string. When you need a token's value, read Theme.qml, don't
copy hex into a component.

**Surfaces step by lightness, not by border.** The ladder is `bg →
bgDeep → surface → surface2 → surface3`. 1px `line` is the strongest
divider; `lineSoft` for quieter, `lineStrong` only on hovered cards or
edges that need to grab attention.

**Text** is `text` / `text2` / `text3` for primary / secondary /
tertiary. Inverse text (`textInv`, `accentText`, `accentInk`) sits on
top of accent-filled chips and buttons.

**Accent** is the one warm color in the viewport, used for the primary
affordance on the current page (Run, Record arm, Save) or the selected
patch in the sidebar. Use `Theme.accentWash(alpha)` for selection
backgrounds so they track the active palette; never hardcode a
selection color. (An old static `accentWash` property once collided
with the helper of the same name and silently desaturated every
selected row in dark mode, so the helper is the only way.)

**Category tints** are functional, not decorative. Each action kind has
its own chip color, used only on the small category pill that labels
the action row. Branched by palette so the saturated original set
rides with Cool Slate and the muted ink-* register (mirrored from
wflows.io tokens.css) rides with Warm Paper. Look up via
`Theme.catFor(kind)`; the full set lives in `qml/Theme.qml`. Categories
include the action kinds (key, type, click, move, scroll, focus, wait,
shell, notify, clipboard, note) plus the flow-control wrappers
(when, unless, repeat, use).

### Typography

- **Hanken Grotesk**, body, UI, headings (400 / 500 / 600 / 700). A
  well-built variable grotesque, warmer and less corporate than
  Inter / Geist.
- **Geist Mono**, all technical values, commands, key chords, paths,
  numeric readouts. Paired deliberately for modern-product-UI
  readability.

Two fonts, period. No display, handwriting, or industrial faces.

Reflex list still banned (Inter, Fraunces, Newsreader, Lora, Crimson*,
Playfair, Cormorant, Syne, IBM Plex*, Space Mono/Grotesk, DM*, Outfit,
Plus Jakarta, Instrument*).

Fixed `rem` scale, six steps, mirrored on the Theme singleton:

```
fontXs:   11px    labels, small-caps category chips
fontSm:   13px    secondary UI text, mono values
fontBase: 14px    primary body
fontMd:   16px    section titles
fontLg:   20px    page titles
fontXl:   28px    display (rarely used)
```

### Radii ladder

Pick from the ladder, don't free-hand corner radii. Mirrors wflows.io's
full set:

```
radiusXs:   4    tags
radiusSm:   6    compact buttons / inputs
radiusMd:  10    cards, dialogs
radiusLg:  16    hero / big cards
radiusXl:  22    large panels
radiusPill: 999  primary / secondary buttons, triggers
```

### Spacing scale

4pt scale with semantic names on Theme: `s1` (4) → `s8` (64). Use `gap`
for sibling spacing, not margins. Vary spacing for hierarchy; don't
apply the same padding everywhere.

### Design Principles

1. **Surfaces step by lightness.** The hierarchy `bg → surface →
   surface2` is brightness alone. 1px `line` hairlines are the
   strongest divider drawn; beyond that, change the fill.

2. **Rounded, consistent.** Pick from the radii ladder above. Don't
   free-hand corner radii.

3. **Flat, not skeuomorphic.** No gradients on surfaces, no embossed
   edges, no drop shadows except for a true overlay (dialog backdrop
   only). No photo textures.

4. **Category color is functional.** Tint only on the chip; accent is
   orthogonal and signals active / selected.

5. **Type hierarchy > visual weight.** Titles 20px / 600, body
   14px / 400, values Geist Mono 13px. These three do most of the work.

6. **Hover subtle, selection clear.** Hover raises one surface step
   (cards may swap their border from `line` to `lineStrong`) and is
   instant. Selection uses a coral-washed background plus an `accent`
   border, sourced through `Theme.accentWash(alpha)`.

### Motion

Qt Quick native declarative animation, used restrainedly.

- StackView push / pop: 160ms `Easing.OutCubic`
- Row expand / collapse: 180ms `OutCubic` via height `Behavior`
- Hover: no animation; instant fill swap. Hover animation is a web tic.
- REC armed: opacity pulse 1.0 ↔ 0.7 at 1.1s, steady when recording
- A `reduceMotion` setting zeroes all durations

### Accessibility

- Contrast ≥ AA on every text-on-surface combination in both palettes
  and both modes.
- Full keyboard nav, tab order matches visual order.
- Focus ring: 2px accent outline with 2px offset on the focused
  element.
- Qt font rendering handles subpixel / hinting natively.

## Stack

- **Qt 6.11 + Qt Quick (QML)**, UI
- **Rust**, engine (actions, runner, store, recorder, KDL serde)
- **cxx-qt 0.8**, Rust ↔ Qt bridge (Rust types as QObjects)
- **CMake**, build driver; invokes Qt's moc / rcc / qmltyperegistrar and
  cargo under the hood

One binary. No IPC, no webview. Engine crate is UI-agnostic enough that
a future `wflow-engine` daemon could reuse it behind a D-Bus interface.
